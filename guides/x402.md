# x402

x402 gives the old HTTP 402 status a real use: a paid route says what it costs, and the agent pays and retries with no account.

Like all commerce checks, this one only counts on sites detected as stores.

**Passes when** the scanned page, `/api` or `/api/v1` answers 402 and shows it is x402, through an `x-payment*` or `x402*` header, a `WWW-Authenticate` mentioning x402, or a JSON body with `x402Version` or an `accepts` array.

```http file=/api
HTTP/1.1 402 Payment Required
Content-Type: application/json

{
  "x402Version": 1,
  "error": "payment required",
  "accepts": [
    {
      "scheme": "exact",
      "network": "base",
      "maxAmountRequired": "10000",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "payTo": "0x0000000000000000000000000000000000000001",
      "resource": "https://example.com/api",
      "description": "One API call",
      "mimeType": "application/json"
    }
  ]
}
```

Replace the example `payTo` with your own wallet. The official middleware for Express, Hono and Next.js builds this answer for you.

## Easy mistakes

- Having paid routes only on other paths. This check cannot find them, so keep one at `/api` or `/api/v1`.
- A bare 402 with no details. An agent cannot pay without knowing what and where.
